## 0. 배경과 원칙

- 독립 검증 결과: 필수 1~26번·31번 통과, **27번(제출 전 점검) 실패** — 화면 캡처 부재, 기획 검증(8.7) 결과 문서 부재, 체크리스트 칸(결과·증빙·비고) 미기입. 11·20·8·21번 약화 지점은 D18~D21로 코드 보완 완료(문구 교정만 남음).
- 구조 사실(원본·복사본 동일, 병합·수식 일치 확인함): 시트 1개 `체크리스트`(B2:I47), 번호 1~32 = 행 9~40, 결과 G·증빙 H·비고 I. G9:G40 데이터 유효성(통과/실패/미확인/해당없음), C3 유효성(셀프/상호), 조건부 서식, 집계 F42:F47(`COUNTIF($G$9:$G$40,…)`·`COUNTBLANK`·`COUNT`). 현재 복사본은 28~30·32번만 `해당없음`이고 G·H·I의 1~27·31번은 비어 있다.
- **허위 통과 금지**: 결과 `통과`는 §3의 "직접 실행 근거"가 있을 때만. 못 한 것은 `미확인` + 비고 사유. 실행하지 않은 것을 "통과(코드 리뷰상)"로 쓰지 않는다.
- 외부 API 실호출은 이번 작업에서 **하지 않는다**(OpenDART IP 차단 이력, 메모리). 2026-11-20에 수행한 실호출 기록은 "기존 실행 기록 인용"으로만 사용한다(§3 근거 등급 B).

## 2. 복사본 xlsx 문구 교정 (번호별 대조 규칙)

**규칙**: 번호 n의 복사본 E(확인 항목)·F(확인 방법)가 원본 n의 요구를 **모두 포함**해야 하고(약화 금지), 이 앱에 맞게 구체화만 허용. 원본 E·F의 모든 명사구(예: "재사용", "실패 응답 형식", "구분되어", "기본값", "밝혀진다")를 체크리스트로 만들어 복사본에 대응 표현이 있는지 번호별 표로 점검한다. 교정은 아래 표 외에 추가 번호가 대조에서 발견되면 같은 규칙으로 처리한다.

| 번호 | 교정 내용 |
|---|---|
| 1 | "Tool 3종" → "외부 API Tool 3종(…) + 로컬 Tool 1종(search_filing_text, 심화 F3022)". 외부 API 툴/로컬 툴 구분은 `kind` 필드(D1c)로 구분됨을 명기하고 "로컬 서버 API 툴(심화, 이번 범위 없음)" 문구 삭제. 방법 ①에 `search_filing_text` 포함(`registry.describe()` 4종) |
| 2 | 원문 수준: "요청한 기준과 실제로 조회한 기준이 다르면(예: 미래 날짜) 그 사실이 응답에 밝혀진다". 앱 구체값(`meta.requested_basis ≠ actual_basis`)은 괄호 보조로만 두고, 후보 Tool의 `estimated=true`는 "추정·대체 기준임을 표시" 수준으로 완화(코드 실제 동작에 맞는지 구현 시 D3·D4로 확인) |
| 8 | D20 반영: "Forward PER 등 미지원 지표 요청은 다른 지표로 치환하지 않고 응답에 미지원 고지(`unsupported_metrics`, 체크리스트 8번)"; 방법 ②에 해당 요청 실행·`tests/test_d20.py` |
| 9 | 방법 예시 "은행" → 재계획이 실제 일어난 비금융 요청 "KOSPI 2차전지 중 ROE 15% 넘는 종목"(재계획 1회, session a58afc10-…). 상한 도달은 10번의 "KOSPI 반도체 ROE 200%·부채비율 1%"로 교체. 은행이 금융업 미지원(D4a)으로 재현 불가한 점은 비고 |
| 11 | D18 반영: "직전 응답 요약(top)이 후속 요청 해석에 반영", 방법에 `tests/test_d18.py` 추가 |
| 20 | D19 반영: "핵심 값 = 사용자 판단 기준값(target_per·target_roe)·재검토일·이름·메모 수정과 삭제 … 종목·기준일·지표·산업 평균·공시는 불변(변조 방지)"; "지표 값은 근거 보존을 위해 수정 불가" 단독 문구 제거. 방법에 PATCH 허용 필드 외 422 확인 |
| 21 | D21 반영: "/docs에 응답 스키마(responses)까지 노출되어 명세와 대조 가능, 런타임 응답은 불변"; 방법 ①에 응답 스키마 대조 |
| 31 | 복사본 I39("구현 시 기입…")를 실제 상태로: 심화 F3022 **선택·구현함**, 색인 8종목 실데이터 비교 완료(D17-rag-comparison.md). 번호 31은 `해당없음`이 아님 |
| 28~30·32 | `해당없음` 유지. 비고: "선택하지 않은 심화 항목(F3020·F3021·F3023 미선택, README §8 제외)" — 사유 문구만 이 문장으로 통일 |
| 그 외 | 대조 규칙으로 약화가 발견된 번호 수정. 예상 점검 대상: 10(1~3회 → "상한 도달 시 사유와 함께 응답"), 12(제외 사유), 15(구독 해제 방법), 25(키 비움 화면) |

## 4. xlsx 편집 방법

- `python3`+openpyxl(`load_workbook`, 기본값; `data_only` 쓰지 않음). 복사본만 열어 셀 값만 대입(`ws["E9"].value = …`). 병합·서식·열 너비·행 높이·데이터 유효성·조건부 서식은 openpyxl이 유지하는 범위를 쓰되 **저장 후 아래를 재확인**:
  1. 재로드 후 `merged_cells.ranges`가 편집 전과 동일, F42:F47 수식 문자열 동일, 열 너비·행 높이 동일, G9:G40·C3 데이터 유효성 2개 존재, 조건부 서식 범위 동일.
  2. 편집 전 복사본을 임시 디렉터리에 백업해 셀 단위 diff로 **변경 셀이 E/F(교정)·G/H/I(기입)·C3 외에 없음** 확인.
  3. G열 값은 유효성 목록 4값만(오타 금지).
  4. 원본 `셀프체크리스트.xlsx` SHA-256 = `af8d0159187683b191715b733035fed9040ff9823268a1efb77b459be0651983` (정비 전·후 동일, 정비 시작 시 값 재계산해 확인). 원본은 열지도 쓰지도 않는다(읽기 대조는 별도 `load_workbook`만).
- openpyxl 저장으로 유효성·조건부 서식이 사라지거나 서식이 깨지면 중단하고 보고(대안: 압축 해제 후 `sheet1.xml` 문자열 치환 — 구현 시 확인 항목).
- 장문 셀은 `wrap_text`가 이미 켜져 있다. 행 높이가 문구를 가릴 정도면 행 높이만 키운다(허용 변경).
