# D12a 리포트 수정 범위 명시 (문서·안내만)

기준: DESIGN §8(수정 가능 필드 `name`·`memo`만)·§9(`PATCH {name?, memo?}`), D12 §4(`extra="forbid"`)·§7(스냅샷), D15 §7(수정 폼), invest-helper.md F3015·F3016, 셀프체크리스트 20번(E28). **기능·API·DB 변경 없음.**

## 1. 목적

F3016 첫 항목은 "저장한 계획의 **핵심 값**을 수정할 수 있어야 한다"인데, 우리는 근거 보존을 위해 `name`·`memo`만 수정할 수 있다. 채점자가 "핵심 값 수정 미충족"으로 읽지 않게 **결정과 근거를 README와 화면에 드러낸다.** 근거는 이미 명세에 있다.
- invest-helper.md 매핑 표: F3015~F3016 → "간소화 … **수정은 핵심 값 일부만**".
- F3016 예시: "리포트 관리 화면에서 **메모와 표시 이름**을 고치거나 리포트를 삭제하면 목록에 바로 반영한다." → 현재 구현과 그대로 일치한다.

## 2. 변경 범위

| 파일 | 위치 | 변경 |
|---|---|---|
| `README.md` | §8 구현 범위, "제외:" 줄 바로 아래 | 불릿 1개 추가(§3-1) |
| `frontend/reports.js` | `editBlock`의 `form` 자식 배열, 메모 `textarea`(`mi`) 다음, `save` 앞 | `el("p", { class: "hint", text: EDIT_NOTE })` 1개(§3-2) |
| `frontend/style.css` | `.save-form, .edit-form` 규칙 근처 | `.hint { margin: 0; font-size: .8rem; color: var(--muted); }` 1줄 |

- 화면 안내가 필요하다고 판단한 이유: 채점자는 README보다 화면을 먼저 볼 가능성이 높고, 수정 폼에 이름·메모만 있으면 "지표는 왜 못 고치나"가 곧바로 생기는 질문이다. 안내는 수정 폼을 열었을 때만 보이므로 평소 화면은 그대로다.
- 목록·상세 상단 같은 다른 위치에는 넣지 않는다(중복).
- DESIGN.md: **수정 제안 없음.** §8이 이미 "수정 가능 필드: `name`, `memo`만(F3016). 지표 값은 불변 — 근거가 바뀌지 않게."라고 적고 있어 충돌이 없다.

## 3. 문구 초안

### 3-1. README §8 추가 불릿 (그대로 붙여 넣음)

```
- 리포트 수정(F3016): 이름(`name`)과 메모(`memo`)만 고칠 수 있고, 리포트 삭제도 할 수 있다. 수정·삭제 결과는 리포트 화면에 바로 반영된다. 종목·기준일·지표 값·산업 평균·공시 목록은 수정할 수 없다. 이 값들은 Tool(외부 API)이 조회한 결과를 저장 시점 그대로 남긴 근거라서, 손으로 고치면 출처 데이터와 맞지 않는 리포트가 된다. API도 `PATCH /api/reports/{id}`에 `name`·`memo` 외 필드가 오면 422로 거부한다. 다른 기준일이나 종목이 필요하면 채팅에서 다시 분석한 뒤 새 리포트로 저장한다. 명세 F3016 예시("메모와 표시 이름을 고치거나 리포트를 삭제")와 같은 범위다.
```

### 3-2. reports.html 수정 폼 안내 (`EDIT_NOTE`, reports.js 모듈 상수)

(D12b §6-3이 이 문구를 대체한다.)

```
지표·기준일은 분석 당시 조회한 근거라 수정할 수 없습니다. 바꾸려면 채팅에서 다시 분석해 새로 저장하세요.
```
- `textContent`로만 넣는다(`el`의 `text` 옵션, D15 §10 규칙 그대로). `module.exports`에는 추가하지 않는다.

## 4. 테스트 관점

- 기존 테스트(`tests/test_d15.py`, `tests/frontend/d15.test.js`, D12 PATCH 422 테스트)가 무수정으로 통과해야 한다. 동작이 바뀌지 않으므로 새 단위 테스트는 만들지 않는다.
- 수동: 상세 → `[이름·메모 수정]` → 메모 칸 아래, 저장 버튼 위에 안내 한 줄이 보이고 `[취소]` 시 폼과 함께 사라짐. 좁은 폭에서 줄바꿈되고 가로 스크롤이 생기지 않음.

## 5. 구현 시 확인 항목

- `el()`이 `class`·`text`를 동시에 받는지 확인한다(reports.js 223행 `p()` 헬퍼가 같은 형태를 쓴다).
- `.edit-form`이 grid/flex 레이아웃이라면 `p.hint`가 폼 전체 폭을 차지하는지 확인하고, 아니면 해당 규칙에 맞춰 `grid-column: 1 / -1` 등을 추가한다.
- README 불릿 속 "422로 거부" 문장이 실제 코드(`extra="forbid"` → `INVALID_REQUEST` 422)와 일치하는지 테스트 이름이나 코드로 확인한다.
