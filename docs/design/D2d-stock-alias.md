# D2d 종목 통칭 별칭 (resolve_stock 보정)

상위: D2 §4(`resolve_stock`). D0 변경 불필요(반환 타입·에러·`matched_by` 값 집합 그대로).

## 1. 목적
"현대차" 같은 흔한 통칭이 엉뚱한 종목으로 `ok` 확정되는 것을 막는다. 최소 수정: 기존 매칭 단계 앞에 작은 별칭 표 1회 조회만 추가.

## 2. 원인
D2 §4-3은 정확→접두→포함 순으로 **처음 hit가 나온 단계에서 멈춤**. `norm_name("현대차")="현대차"`는 "현대자동차"의 접두·부분 문자열이 아니고, "현대차증권"의 접두로 1건 hit → `ok(001500 현대차증권, prefix)`. 통칭은 정식명과 문자열 관계가 없을 수 있어 기존 단계로는 해결 불가.
영향: `resolve_stock` 호출처 전부(`agent/nodes/plan.py`, `execute.py`, `respond.py`) — 공유 함수 한 곳에서 고치면 전부 해결.

## 3. 변경 범위
`backend/identity/resolve.py`만. (+ `tests/test_d2.py` 테스트 추가)

1. 별칭 표 = **코드 상수** `_ALIASES` (`resolve.py` 모듈 상단). 10여 개 고정값이라 JSON·로더·검증 로직(industry_terms.json 패턴)은 과함. 키는 로딩 시 `norm_name`으로 정규화: `_ALIASES = {norm_name(k): v for k, v in {...}.items()}`.
2. `resolve_stock` 흐름 (코드 경로 §4-1, 빈 문자열 처리는 기존 그대로):
   - `n = norm_name(q)` 이후, `n in _ALIASES`이면 정식명 `a = norm_name(_ALIASES[n])`으로 **정확(`name_norm=?`, `listed=1`) 단계만** 조회.
     - hit ≥1 → 기존 규칙대로 반환(1건 `ok`, 2건 이상 `multiple`, `matched_by="exact"`).
     - hit 0 (정식명이 DB에 없음: 상장폐지·개명 등) → **원 질의 `n`으로 기존 정확→접두→포함 단계 그대로**(안전 폴백).
   - 별칭 키가 아니면 기존 동작 100% 동일.
3. 구현 팁: 기존 stage 루프를 `_match(n, stages)` 헬퍼로 빼서 별칭(정확 단계 1개)과 원 질의(3단계)에 재사용. 별도 `matched_by="alias"` 값은 추가하지 않는다(Literal·D2 타입 변경 회피).
4. 대소문자·공백·`(주)`·구두점 정규화는 `norm_name` 그대로(키·값 모두 동일 함수 통과).

## 5. 테스트 관점
- 신규(`test_d2.py` 픽스처 CORPS에 `("005380","…","현대자동차")`, `("001500","…","현대차증권")`, `("000270","…","기아")` 추가):
  - `resolve_stock("현대차")` → `ok`, 005380, `matched_by="exact"`.
  - `resolve_stock(" 기아 차 ")` → `ok` 000270 (공백 정규화 후 별칭 키 일치).
  - 폴백: 정식명이 픽스처에 없는 별칭(예: "삼바") → 원 질의 기존 단계 결과(`none`)와 동일.
  - 별칭 아닌 질의("현대차증권") → 기존대로 exact 001500.
- 기존 테스트 영향: `test_resolve_stock_stages`의 기대값 전부 불변("하이닉스" 제외 이유 §4). CORPS 추가 행은 기존 단언(삼성 계열·카운트)에 걸리지 않는지 구현 시 확인 — 단언이 행 수에 의존하면 별칭 전용 테스트에서 별도 corps로 `Fake(corps=...)` 사용.

## 6. 구현 시 확인 항목
- §4 표의 정식명은 로컬 `invest_helper.db`(읽기 전용 `mode=ro`)에서 `listed=1 AND name=?` 존재 확인함. 캐시 재빌드 후 개명 시 폴백으로 안전하나, 구현 시 같은 쿼리로 한 번 더 확인.
- 참고: 로컬 DB에 "삼성물산"이 2행(000830, 028260) 존재 — 별칭 대상 아님, 정확 일치 시 `multiple` 처리되는 기존 동작 그대로.
- `Fake.fetch_company`는 전역 `CORPS`/`IND`에서 조회하므로 픽스처 행 추가 시 `IND`에도 대응 코드 추가 필요.
